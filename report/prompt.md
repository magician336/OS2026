**[SPECIFICATION]**

#### 一、alloc_proc()

**Pre-Condition**

- 进程控制块结构已定义。
- 内核内存分配器可以使用。

**Post-Condition**

成功时返回一个安全初始化的 PCB：

- `state = PROC_UNINIT`。
- PID 为尚未分配的无效值。
- 运行次数为 0。
- 未分配内核栈。
- 暂无父进程和用户地址空间。
- `context` 和 `tf` 不包含未初始化数据。
- `pgdir` 与当前内核线程共享的内核页表一致。
- 两个链表节点已正确初始化。

**Case 1：内存分配成功**

所有字段进入确定的初始状态，返回 PCB 指针。

**Case 2：内存分配失败**

返回 `NULL`，不解引用空指针，不遗留资源。

**Requirements**

重点检查是否存在未初始化字段，以及链表节点能否安全挂接。

#### 二、copy_mm()

**Pre-Condition**

- 目标 PCB 已经分配。
- 当前创建的是内核线程。
- 本实验阶段不要求复制完整用户地址空间。

**Post-Condition**

- 新线程与现有内核线程共享内核地址空间。
- 不进行完整的用户页表或内存映射复制。
- `proc->mm` 保持正确的内核线程状态。
- 正常情况下返回成功。

**Case 1：普通内核线程创建**

不分配独立用户地址空间。

**Case 2：遇到不符合当前实验阶段假设的地址空间状态**

依据工程现有接口与约束处理，不虚构尚未实现的用户进程复制机制。

**Requirements**

明确区分：

- 共享内核页表。
- 共享用户地址空间。
- 复制用户地址空间。

不得把这三种行为混为一谈。

#### 三、copy_thread()

**Pre-Condition**

- PCB 已成功分配。
- 新线程已经拥有独立内核栈。
- 输入 `tf` 指向有效的中断帧。

**Post-Condition**

- 新线程的中断帧存放在自身内核栈的合法位置。
- 中断帧内容来自输入模板。
- 子线程的返回值寄存器 `a0` 设置为 0。
- 栈指针符合调用约定和输入参数要求。
- `context.ra` 指向 `forkret`。
- `context.sp` 指向首次运行需要的栈位置。
- 所需栈对齐约束得到满足。

**Case 1：调用者未提供单独栈地址**

使用新线程自身内核栈构造合法的初始现场。

**Case 2：调用者提供有效栈地址**

按照函数接口语义处理该栈地址。

**Requirements**

特别检查：

- 是否越过内核栈边界。
- `struct trapframe` 的大小和对齐。
- `context.sp` 与 `tf` 的关系。
- `a0=0` 的含义。
- 首次执行是否能进入正确的恢复链路。

#### 四、do_fork()

**Pre-Condition**

- 当前执行线程有效。
- 输入中断帧有效。
- 进程管理全局数据结构已经初始化。

**Post-Condition**

成功时：

- 新线程拥有独立 PCB 和内核栈。
- 正确建立父子关系。
- 正确设置内存管理关系。
- 正确准备中断帧和上下文。
- 获得唯一且合法的 PID。
- 被登记到必要的进程管理结构。
- 进程总数正确增加。
- 进入 `PROC_RUNNABLE` 状态。
- 返回新线程 PID。

失败时：

- 返回对应的负错误码。
- 释放已分配但不再使用的资源。
- 不遗留不完整的进程结构。
- 不错误修改进程数量和链表。

**Case 1：进程数量达到上限**

拒绝创建，返回进程数量相关错误码，不分配新资源。

**Case 2：PCB 分配失败**

返回内存不足错误，不留下资源。

**Case 3：内核栈分配失败**

释放已分配 PCB，保持全局状态不变。

**Case 4：地址空间处理失败**

按资源取得的逆序回收已占用资源。

**Case 5：创建成功**

完成所有可能失败的初始化步骤后，再分配 PID、登记线程并使其进入可运行状态。

**Requirements**

- 重点检查资源分配和释放是否对称。
- 避免在线程尚未完整初始化时提前发布。
- 按工程要求保护共享的进程管理结构。
- 中断状态必须被正确恢复。
- 不得让失败路径改变 `nr_process` 或留下失效链表节点。

#### 五、kernel_thread()

**Pre-Condition**

- 提供合法的线程入口函数。
- 已具备创建线程所依赖的内核基础设施。

**Post-Condition**

- 正确构造临时中断帧。
- 将线程入口函数和参数放入与 `kernel_thread_entry` 对应的寄存器。
- 正确设置首次运行所需的状态寄存器位。
- 使首次执行入口指向 `kernel_thread_entry`。
- 通过 `do_fork()` 创建线程。
- 返回新线程 PID 或相应错误码。

**Case 1：正常创建**

新线程能够在后续被调度时调用指定函数，并传入正确参数。

**Case 2：创建失败**

原样传递合理的失败状态，不伪造成功 PID。

**Requirements**

重点核对：

- `s0`、`s1` 的用途。
- `SSTATUS_SPP`、`SSTATUS_SPIE`、`SSTATUS_SIE` 的含义。
- `CLONE_VM` 在当前接口中的作用。
- 首次执行 PC 与线程入口函数之间的关系。

#### 六、proc_init()

**Pre-Condition**

- 内核已经完成必要的内存管理初始化。
- 启动阶段的内核栈可用。
- 进程管理模块尚未完成初始化。

**Post-Condition**

- 全局进程链表正确初始化。
- PID 哈希表各桶正确初始化。
- 创建并初始化 idleproc。
- `current` 正确指向 idleproc。
- 创建第一个普通内核线程 initproc。
- 两个线程的 PID 和状态正确。
- 进程总数与实际已创建线程一致。
- 后续调度能够找到 initproc。

**Case 1：初始化 idleproc**

idleproc：

- PID 为 0。
- 使用启动阶段已有的内核栈。
- 不通过普通 `fork` 路径创建。
- 处于 `PROC_RUNNABLE` 状态。
- 需要重新调度的标志被设置。
- 成为当前线程。

**Case 2：创建 initproc**

- 通过 `kernel_thread()` 创建。
- 入口函数为 `init_main`。
- PID 符合预期。
- 能通过进程查找接口定位。
- 线程名称正确。

**Case 3：关键资源初始化失败**

按照框架约定执行错误处理，不得继续使用无效 PCB。

**Requirements**

- 区分 idleproc 与 initproc 的创建方式。
- 不重复分配启动线程内核栈。
- 维护正确的线程数量。
- 不在本函数中提前执行成员 C 的调度职责。

#### 七、测试与验收规格

##### 1. PCB 初始化测试

检查：

- 分配成功时各字段是否正确初始化。
- 分配失败时是否安全返回。
- 链表节点是否处于合法状态。

##### 2. 线程创建测试

检查：

- idleproc PID 是否为 0。
- initproc PID 是否为 1。
- `current` 是否为 idleproc。
- initproc 是否处于可运行状态。
- 父子关系是否正确。
- 是否能够通过 PID 查找 initproc。
- 是否正确共享内核页表。

##### 3. 上下文测试

检查：

- 新线程 trapframe 是否位于合法的内核栈空间。
- 栈地址是否正确对齐。
- 子线程返回值寄存器是否为 0。
- `context.ra`、`context.sp` 是否正确。
- 首次运行入口和参数传递是否符合汇编代码。

##### 4. 错误路径测试

尽可能通过独立测试桩模拟：

- PCB 内存分配失败。
- 内核栈分配失败。
- 创建数量达到上限。
- 地址空间处理错误。

检查资源是否释放、进程计数是否保持正确，以及链表是否未被污染。
